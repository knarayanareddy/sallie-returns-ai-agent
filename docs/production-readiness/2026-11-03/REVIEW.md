## Architecture and product boundary

The repository exposes two separate surfaces in the sampled tree: a static Pages site (`index.html`, workflow HTML files) and a Python Flask preview under `returns_pipeline/version_a/app.py` (local evidence: `evidence/sallie-returns-ai-agent/snapshot.json`; [`app.py:39-53`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/app.py#L39-L53)). The sampled Flask preview imports a `SupervisorOrchestrator` plus helper functions for receipt verification, payment-token lookup, stock queries, hold acquisition, transfer manifests, supplier claims, and customer notification.

The inspected `tools.py` materially narrows the product claim. Its module header says the code is provided so the pipeline can be “`tested end-to-end without depending on external systems`” and that each function would need real POS, WMS, CV, supplier, or notification wiring “`In production`” ([`tools.py:4-11`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L4-L11)). ## Findings ledger

- **SR-1 — High, confirmed static:** [`requirements.txt:1-3`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/requirements.txt#L1-L3) ends with a literal `EOF`. This is not a normal dependency declaration and can break clean installation unless such a package exists. Correct the file, then record a reproducible lock/install path before asking reviewers to run anything.

- **SR-2 — Medium, confirmed static:** the sampled implementation is explicitly mock-backed, but the current draft did not say that strongly enough. `tools.py` says the pipeline is provided so it can be “`tested end-to-end without depending on external systems`” ([`tools.py:4-11`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L4-L11)). Receipt and payment lookup use a mock ledger ([`tools.py:169-171`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L169-L171), [`tools.py:370-372`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L370-L372)); inventory holds mutate `MOCK_INVENTORY` and `active_holds` in memory ([`tools.py:455-459`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L455-L459), [`tools.py:473-500`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L473-L500)); supplier submission returns `None` unless `SUPPLIER_API_AVAILABLE` is enabled ([`tools.py:636-656`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L636-L656)); and customer notification “`returns a mock delivery record`” ([`tools.py:669-699`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L669-L699)). Correction: label these effects as simulated until authoritative services are wired and observed.

- **SR-3 — Medium, confirmed static:** the sampled Flask preview applies wildcard CORS to every response and explicitly handles cross-origin `OPTIONS`. `_cors_headers` sets `Access-Control-Allow-Origin` to `*`, allows `GET, POST, OPTIONS`, and `before_request` returns a `204` preflight response with those headers ([`app.py:68-88`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/app.py#L68-L88)). This is an observed exposure policy, not proof of an exploit; the sampled prefix does not establish cookies, auth tokens, or a successful cross-site state-change attack. Correction: if this preview is kept browser-accessible, scope allowed origins and methods intentionally and reassess once auth or sensitive data is introduced.

- **SR-4 — Medium, unverified risk:** the preview advertises that operators can “`approve / reject / escalate`” cases ([`app.py:5-10`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/app.py#L5-L10)), but the sampled prefix does not prove authentication, role authorization, CSRF mitigation, or durable audit enforcement on those actions. ## Five-discipline assessment

- **Correctness / code review:** the reviewed SHA contains a real code path, but the sampled helper layer is intentionally mock-based. `verify_receipt_data`, `payment_token_lookup`, hold acquisition, supplier claims, and notifications all describe production behavior separately from current behavior ([`tools.py:164-171`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L164-L171), [`tools.py:367-372`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L367-L372), [`tools.py:447-500`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L447-L500), [`tools.py:636-699`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/tools.py#L636-L699)). That makes production-readiness claims dependent on uninspected integrations.

- **Automation / testing:** sampled evidence supports executable demo scenarios, not independent tests. `demo.py` defines five named cases plus `case_4b`, runs them from `main()`, and prints a story of expected outcomes; it does not show assertion logic or CI orchestration in inspected material ([`demo.py:200-369`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/demo.py#L200-L369), [`demo.py:384-413`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/demo.py#L384-L413)). The malformed `requirements.txt` also blocks confidence in a clean baseline.

- **DevOps / operations:** publication evidence shows a successful Pages build and no collected workflow/hook metadata for backend deployment ([publication evidence](../../publication-evidence/sallie-returns-ai-agent.json)). Hosting, observability, release identity, restore process, and secret management for any non-static backend remain unverified.

- **OWASP / security:** the only directly observed server-side security behavior in sampled code is permissive wildcard CORS on the Flask preview ([`app.py:68-88`](https://github.com/knarayanareddy/sallie-returns-ai-agent/blob/2eae62442129c71098fb6349f31d2842b837d9e9/returns_pipeline/version_a/app.py#L68-L88)). Authentication, authorization, CSRF defenses, log redaction, secret handling, and customer-data controls were not proven in the sampled ranges. Because notification, payment-token, and cross-store lookup functions are mock-backed, this review does not assert a live data-protection failure.

- **UI/UX / accessibility:** both the static Pages demo and the Flask preview are user-facing, but no browser execution or accessibility review occurred. The main UX issue visible in source is product-boundary clarity: sampled code and README/demo copy make it easy to confuse simulated outcomes with live service effects unless the surfaces are explicitly labeled as demo/mock mode.

## Production blockers and owner questions

- Is this repo intended to remain a demo, or should it become a live retail workflow with real refunds, stock locks, supplier claims, and customer messaging?
- Which systems are authoritative for POS receipts, inventory reservations, courier dispatch, supplier RMAs, and notifications?
- Who is allowed to approve, reject, or escalate exceptions, and where is that identity enforced?
- Should the Flask preview remain cross-origin callable by any site, or only by a specific Pages/demo origin?
- What is the intended evidence standard for “regression test cases”: demo scenarios, assertion-backed tests, or both?
- What are the release, rollback, backup, retention, and synthetic-data policies for any non-static deployment?
